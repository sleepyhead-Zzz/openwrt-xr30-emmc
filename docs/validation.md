# Offline acceptance and limits

The workflow fails closed: a missing image or failed required check prevents the `candidate` artifact from being created. Failure logs are separate artifacts and are not boot recommendations.

1. Validate locked OpenWrt commit, feed commits, official configuration file hashes, single XR30 target selection, RAM-only outputs and preserved official kernel options.
2. Download all eight USTC target/base/kmods/LuCI/packages/routing/telephony/video indexes using GET; reject another-mirror redirects. Verify signatures using the built official apk tool and the image's trusted public keys. No allow-untrusted or dependency bypass is used.
3. Compare the actual kernel config ABI with the published 25.12.5 filogic ABI. OpenWrt's APK files are authenticated through the signed index and package identity/data digests, rather than an individual APK signature. Use normal `apk fetch` and a script-free `apk add` in an isolated fakeroot directory to verify and unpack official `kmod-usb-net-asix`; compare its ELF vermagic with the same locally built module. No `allow-untrusted` flag is used to consume repositories or packages. Enable the official kmod URL only on a match. Preserve same-build local packages and their signed index independently of the result.
4. Parse the final FIT independently in Python. Check default config-1, all kernel/DTB/ramdisk references, ARM64 architecture, kernel compression/header/load/entry, DTB address, RAM bounds, internal CRC/SHA hashes, complete XR30 DTB and all required board properties.
5. Parse the gzip/newc initramfs actually contained in the final FIT. Inspect init/preinit, board defaults, packages, kernel module dependencies/vermagic, trusted repository URLs, and absence of injected device credentials, persistent root selectors, environment tools and block automount packages.
6. Extract that exact initramfs on the ephemeral GitHub runner and run its official board detector, network generator and ucode wireless generator under ARM64 userspace emulation. Use synthetic sysfs/radio data in both 2G-first and 5G-first orders. Confirm LAN address, three bridge ports, WAN DHCP, DHCP-server settings and two enabled open XR30 APs in CN. Do not start init or mount the host's devices into this chroot.
7. Audit the official startup path: `/init` exports INITRAMFS and copies the root to tmpfs; disk root preinit is skipped. A small board-specific base-files guard skips the late `mount_root done` call, and the test executes that function with mount_root replaced by a failing spy. The command line also disables the fstools GPT-partname scan. The DTS exposes factory nvmem without a production rootdisk or NAND nodes, block automount helpers are absent, and the official bootcount function performs no XR30 write action. This is a static startup audit plus targeted execution, not full-system emulation.
8. Against a copy of the final rootfs APK database, refresh signed indexes and simulate an ordinary `htop` installation. When official kmods match, simulate `kmod-usb-net-asix` installation as well. Keep the logs and exact results.

The successful status is **“构建及离线检查完成，尚未实机验证”**. Runtime clock selection, radio detection and RF behavior, link/LED/button behavior, USB operation, memory use, bootloader entry and fallback/recovery capability require later physical tests. A kernel ABI/hash match is evidence for module compatibility, not proof that every optional third-party package will work. RAM-boot correctness does not grant permission to write an image or change U-Boot.

The generator test supplies the normal RAM runtime directories and an isolated `/dev/null` device; it never mounts host `/dev` or `/sys`. Generated root-owned UCI files are read through the chroot. The support package must be `1.0.0-r2`, which normalizes the replaced network JSON before adding ports, address and protocol. Earlier `r1` artifacts failed this test and are not candidates. The regression was reproduced and its correction tested against the extracted image before starting a new full build; a modified test copy is not delivered as firmware.
