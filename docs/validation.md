# Validation gates and limits

1. Preserve locked official source, feeds, kernel inputs and mt76. Validate required packages and single XR30 target after defconfig.
2. Validate rescue inline FIT and production external/static FIT independently: all hashes, bounds and nonoverlap, 4 KiB alignment, kernel/DT load and entry addresses, complete XR30 hardware properties, legacy U-Boot overlay selection. Apply the no-op overlay with fdtoverlay and compare every DT node/property.
3. Rescue must have an initrd and RAM cmdline, with no production binding. Production must have SquashFS loadable, no ramdisk, a production rootdisk phandle, F2FS overlay cmdline and metadata supported_devices exactly [cmcc,xr30-emmc].
4. Inspect the actual CPIO/SquashFS package database and required storage tools. Verify the signed USTC indexes, normal package dependencies and official kmod ABI/vermagic without bypassing verification.
5. Under ARM64 qemu-user, run real network/wireless generators with both radio enumeration orders and DHCP checks. Run actual late-init, fstab and block hotplug logic with spies, once in rescue mode and once in production mode. Require the production path to initialize overlay/mount data and the rescue path to skip both. Check official bootcount makes no environment writes.
6. On an exclusively CI-owned sparse disk, use image-native sfdisk for the old-to-new GPT transition. Require exact geometry and unchanged first-three partition records and content. Format data with image-native mkfs.ext4 and writable root with image-native mkfs.f2fs. Verify capacity greater than 11 GiB and file I/O at 5 GiB, and persistence of an overlayfs merged-root write after unmount/remount.
7. Run the image's official emmc_upgrade_fit and emmc_copy_config against the production loop partition. Verify both GPT copies, p1–p3 and SHA-256 of the entire p5 remain unchanged, then remount ext4 and verify its marker file. CI explicitly models FIT block extents with loop devices; it does not run the physical XR30 kernel or U-Boot.
8. Publish candidates only after all gates pass. Include both images, checksums, manifests, source/feed locks, geometry, reports and installation instructions. Recheck all hashes after local download.

The fstools FIT volume byte conversion has a local uint64_t cast before shifting sectors by 9, avoiding truncation above 4 GiB. The format-selection path already uses BLKGETSIZE64; this change preserves official filesystem behavior and kernel ABI.

No physical disk boot, persistence across router reboot, physical factory reset, hardware throughput or new rescue boot is claimed by these offline tests. The previous successful RAM hardware baseline is preserved separately. A future installation must revalidate actual geometry and backups before modifying the disk.
